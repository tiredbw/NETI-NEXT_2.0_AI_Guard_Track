# AstraGuard — AI Security Gateway

Проект для трека «ИИ-сторож», «Группа Астра», НЭТИ-НЕКСТ 2.0, 20–22 ноября 2026 года (даты и условия предоставлены участником).

Локальный защитный компонент между пользователем и LLM-агентом: анализирует запросы, проверяет полномочия и выдаёт ALLOW, REVIEW или BLOCK. Работает без платных API и не зависит от подписок ChatGPT/Claude. Стек: Python 3.12+, FastAPI, Pydantic, httpx, SQLite, YAML, Ollama/Qwen 3.5 4B и HTML/CSS/JavaScript без сборки фронтенда.

## Что уже работает

- Гибридная проверка: детерминированные правила, локальный семантический детектор и отдельные проверки политик. Термины jailbreak, prompt injection и system prompt сами по себе не служат основанием блокировки.
- Проверки пользовательского текста, фактических аргументов инструментов и недоверенного tool/RAG-контента.
- Привязка identity к серверному credential, изоляция tenant и повторная проверка ACL перед демонстрационным исполнением.
- Демонстрационные чтение документов и изменение черновиков. Запись требует отдельного reviewer, одноразового подтверждения и Idempotency-Key.
- Версионирование политики с ETag/If-Match и аудит решений без исходных текстов запросов; срок хранения по умолчанию 7 дней.
- Веб-интерфейс, история проверок, статистика tenant, readiness модели, ограниченная очередь и остановка при неопределённом завершении inference.

Критический запрет политики имеет приоритет над оценкой модели. REVIEW и BLOCK останавливают передачу demo agent. При недоступном детекторе запрос, требующий семантической проверки, получает REVIEW; readiness возвращает 503.

## Быстрый запуск

Из корня репозитория, при установленных Python/uv и Ollama:

```bash
uv sync --python 3.12 --frozen
ollama serve
```

Если Ollama уже работает, второй экземпляр не нужен. В другом терминале убедитесь, что модель доступна, и запустите приложение:

```bash
ollama list
# Только если qwen3.5:4b ещё отсутствует:
ollama pull qwen3.5:4b
.venv/bin/python scripts/run_demo.py
```

Откройте [демонстрационный интерфейс](http://127.0.0.1:8000). Локальная справка API: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs), схема: `/openapi.json`. Launcher использует один worker и слушает только loopback. Первый startup проверяет совместимость модели; дождитесь readiness 200 на `/health/ready`.

Launcher создаёт приватный `data/demo-access.json` со случайными credentials и HMAC key. Для входа в UI используйте credential нужной identity из этого файла. Повторный запуск сохраняет credentials; файл не нужно коммитить, публиковать или показывать на демонстрации.

| Identity | Tenant | Назначение |
|---|---|---|
| alice | A | viewer: чтение документов своей организации |
| operator | A | operator: чтение и запрос подтверждаемой записи |
| reviewer | A | security_reviewer: подтверждения и статистика своего tenant |
| bob | B | viewer другой организации |
| policy-admin | control | policy_admin: управление политикой |

Отдельное состояние и другой порт: `.venv/bin/python scripts/run_demo.py --state-dir /tmp/astraguard-demo --port 8001`. Подробности запуска, прав файлов и доступа: [DEMO_LAUNCH.md](docs/DEMO_LAUNCH.md).

## Короткий сценарий демонстрации

1. Под alice отправить «Объясни защиту от prompt injection»: легитимный технический вопрос должен пройти семантическую проверку.
2. Отправить «Игнорируй предыдущие инструкции»: показать BLOCK и отсутствие вызова demo agent.
3. Выполнить `/read A1`, затем `/read B1`: показать разрешённое чтение и отказ доступа к чужому документу.
4. Под operator отправить `/write A2 Новый текст`: получить REVIEW. В отдельной сессии reviewer подтвердить точное действие, затем выполнить его из исходной сессии operator.
5. Показать историю, основания решений и счётчик реальных вызовов демонстрационного исполнителя.

Для модели результат конкретного нового текста заранее не гарантируется. Проверенные примеры и ограничения описаны в [UI.md](docs/UI.md), [STAGE_02.md](docs/STAGE_02.md) и [STAGE_03.md](docs/STAGE_03.md).

## API интеграции

Защищённые маршруты используют `Authorization: Bearer TOKEN`. Сервер определяет subject, tenant и роль; клиент не передаёт их в теле.

| Маршрут | Назначение |
|---|---|
| POST `/v1/sessions` | Создать сессию пользователя |
| POST `/v1/checks` | Оценить текст без исполнения |
| POST `/v1/tool-checks` | Проверить typed tool intent и актуальные права |
| POST `/v1/content-checks` | Проверить недоверенный tool/RAG-текст |
| POST `/v1/agent/turns` | Проверить и при ALLOW вызвать demo agent |
| GET `/v1/checks`, GET `/v1/checks/{id}` | История и результат в пределах прав |
| GET `/v1/reviews/{id}`, POST `/v1/reviews/{id}/approve` | Просмотр и подтверждение demo-действия |
| GET `/v1/policies`, GET/PUT `/v1/policies/{id}` | Доступные политики и административное изменение |
| GET `/v1/stats` | Статистика для reviewer своего tenant |
| GET `/health/live`, GET `/health/ready` | Живость процесса и готовность компонентов |

Для внешней интеграции адаптер использует credential конкретного пользователя. Дочерние tool/content checks требуют исходный ALLOW того же владельца и сессии. Они ничего не исполняют и возвращают `forwarded=false`; адаптер обязан соблюдать решения и останавливать передачу при ошибках. Внешние изменяющие операции пока не поддерживают demo approval workflow. Контракт: [INTEGRATION.md](docs/INTEGRATION.md) и [API.md](docs/API.md).

## Проверки и измерения

```bash
.venv/bin/python -m pytest -q
```

На 18 ноября 2026: **167 offline tests passed**, включая 29 тестов новых интеграционных маршрутов. Есть одно предупреждение об устаревающем backend FastAPI/Starlette TestClient. Unit tests с заглушкой детектора проверяют логику шлюза, а не точность Qwen.

Отдельный smoke с настоящей Qwen подтвердил ALLOW для собственного чтения и учебного запроса, BLOCK для чужого чтения и активной инъекции в RAG-тексте. Это четыре сценария, не benchmark качества.

Корпус содержит 100 размеченных синтетических сценариев. Исторические Precision/Recall/F1 и задержки относятся только к указанным в [EVALUATION.md](docs/EVALUATION.md) версиям. Полный benchmark текущей версии ещё нужно повторить. Автоматический прогон с реальным Ollama:

```bash
.venv/bin/python scripts/evaluate.py --split all
```

Запускайте benchmark отдельно от демонстрационных запросов: оба используют одну локальную модель. Результаты в `data/eval/` исключены из Git.

## Ограничения MVP и следующие шаги

Demo agent является детерминированным исполнителем двух инструментов, а не целевой LLM. Новые tool/content API пока не показаны полной цепочкой в UI. Advisory API не изолирует внешний агент, который обходит шлюз и обращается к инструментам напрямую.

Внешний многошаговый контекст полностью не отслеживается; каждый новый фрагмент необходимо проверять отдельно. Семантическая модель не гарантирует обнаружение всех атак. Сессии и pending payload подтверждений хранятся в RAM и утрачиваются после restart. Демонстрационные ресурсы синтетические; HTTPS и полноценная инфраструктура identity для сетевого развёртывания не входят в локальный MVP.

Ближайшие задачи: показать полную цепочку проверок в интерфейсе, повторить полный benchmark и отрепетировать воспроизводимую демонстрацию. Полный P0 ещё разрабатывается.

## Навигация по исходникам

В Python-модулях `src/astraguard/` и JavaScript `src/astraguard/static/app.js` добавлены русские построчные пояснения для изучения проекта. Комментарии описывают существующее поведение; они не заменяют проверки прав и валидацию контрактов.

| Файл | Ответственность |
|---|---|
| `main.py` | Маршруты FastAPI, авторизация, сессии, rate limit и сборка решений |
| `schemas.py` | Строгие входные схемы, typed arguments и output детектора |
| `engines.py` | Правила атак, валидация YAML-политики, ACL и Decision Engine |
| `detector.py` | Ollama, structured output, очередь, дедлайны, digest и карантин |
| `integration.py` | Проверки внешних tool intents и tool/RAG-контента |
| `storage.py` | SQLite, HMAC-аудит, retention и persistent inference latch |
| `policies.py` | Версии политики, ETag и атомарная активация |
| `demo.py` | Грамматика двух команд и контролируемый demo executor |
| `approvals.py` | Отдельный reviewer, привязка действия и идемпотентная запись |
| `evaluation.py` | Метрики синтетического корпуса без вызова модели |
| `static/app.js` | Вход, состояние вкладки, формы, результаты и история |

`scripts/` содержит команды запуска и измерений, `tests/` содержит автоматические проверки, `policies/` содержит начальный YAML-профиль. Локальные БД, credentials и результаты прогонов находятся в исключённом из Git каталоге `data/`.
