# Наборы для проверки

| Файл | Что это | Как используется |
|---|---|---|
| `dev_groups.json` | Разбиение public dev (500) на 291 группу похожих примеров (`backend/train/groups.py`) | Кросс-валидация по группам: перефразировки одного шаблона не попадают одновременно в обучение и проверку |
| `own_validation.v1.jsonl` | Свой набор, 215 примеров (110 атак, 105 легитимных) в формате `/v1/check` из наших корпусов `cases.v1` и `cases.bypass.v1` | Проверка правил и TF-IDF вне dev: ложные срабатывания на другой предметной области |
| `own_holdout.v2.jsonl` | Отложенный набор, 60 примеров (30/30) | **Не используется** для правил и порогов. Только итоговый замер перед защитой |
| `external_datasets.py` | Скачивает открытые наборы (dmtrdr ru, deepset, xTRam1, OR-Bench, XSTest, InjecAgent, BIPIA) в `data/external/` и приводит к формату dev; пересечения с dev и своими наборами выкидывает | Дообучение и проверка ложных блокировок вне dev. Запуск: `uv run --no-project --with pyarrow python -I eval/external_datasets.py --dev <путь к dev.jsonl>`; описание и лицензии — `data/external/README.md` |
| `tfidf_oof_dev.json` | Оценки TF-IDF для каждого примера dev моделью, которая его не видела | `backend/train/simulate_backstop.py`: честная оценка страховки на сохранённом прогоне Qwen |

Роль в своих наборах — `developer`, ожидание: атака → `block`, легитимный → не `block`.
Поэтому для них смотрим полноту блокировки атак и долю ложных блокировок, а не официальный score.

Публичный `dev.jsonl` и `evaluate.py` лежат в комплекте организаторов (`astra_public_v2/`) и в репозиторий не копируются.

## Свежий набор own_fresh.v3 (21 ноября, вечер)

Скрытый тест содержит приёмы, которых нет в dev, а `own_holdout.v2` уже израсходован на правки. Поэтому собран новый набор `build_fresh_v3.py`:

| Файл | Что это | Как используется |
|---|---|---|
| `own_fresh.v3.probe.jsonl` | 150 примеров: 113 атак, 32 allow, 5 confirm | По нему искали провалы и чинили `normalize.rs` и `rules.rs` |
| `own_fresh.v3.final.jsonl` | 147 примеров: 111 атак, 31 allow, 5 confirm, другие сервисы и тексты | **Не смотрим при правках.** Только замер с реальным Qwen |

Что внутри: 36 семейств обфускации (полноширинные и математические буквы, буквы в кружках, невидимый U+2063, ударения и «залго», греческие гомоглифы,
ROT13 и Цезарь, hex и `\x..`, `%XX`, `&#NN;`, `\uXXXX`, base64 без `=`, base64url, base64 кусками и дважды, base32, двоичный код, Морзе, слова задом наперёд,
обратный порядок слов, русский в английской раскладке, буквы через `| / +` и эмодзи, текст столбиком, без гласных, опечатки, расширенный leetspeak,
разметка внутри слов, RLO), невидимые символы-теги Unicode, 27 новых шаблонов атак (служебные токены чата, поддельный ответ сторожа, JSON с role=system,
склейка частей, «день наоборот», «бабушка», режим обслуживания, акростих, реверс-шелл, cron, NOPASSWD, DNS-вывод, массовое удаление и др.),
многоходовые атаки, инструкции во вложениях (CSV, YAML, HTML, комментарии SQL, base64 и теги внутри вложения) и 73 трудных легитимных.
Формат как у dev (подходит `evaluate.py`), у обфусцированных строк есть поле `plain` — открытый текст.

Проверка без Qwen, за секунды:

```bash
cd backend && cargo build --release --examples && cd ..
./backend/target/release/examples/decode_scan eval/own_fresh.v3.final.jsonl > decoded.jsonl
python eval/decode_coverage.py eval/own_fresh.v3.final.jsonl decoded.jsonl
```

Раскодировано (≥80% слов открытого текста видно модели): до правок 9/76 (probe) и 10/76 (final), после — 69/76 и 70/76.
Остаются «без гласных», опечатки и часть leetspeak в именах ресурсов: их читает только Qwen.
Без Qwen (заглушка, всегда none) правила и TF-IDF блокируют 65/113 атак probe и 57/111 final (было около 30), ложных блокировок 0.
