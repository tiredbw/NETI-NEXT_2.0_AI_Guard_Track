# Демонстрационный интерфейс

Этап 4. Статический same-origin UI поставляется FastAPI: HTML/CSS/vanilla JS, без Node-сборки, CDN, платных API или сторонних шрифтов. Для запуска достаточно Python-окружения и локального Ollama.

## Запуск и вход

```bash
.venv/bin/python scripts/run_demo.py
```

Открыть http://127.0.0.1:8000. Взять bearer token нужного subject из `data/demo-access.json`. Не публиковать этот файл и не показывать его на проекторе.

- `alice`: viewer A — чтение A1, запрет чтения B1 и записи A2.
- `operator`: operator A — чтение A1, запрос изменения A2 через REVIEW.
- `reviewer`: security_reviewer A — рассмотрение и подтверждение разрешимых действий tenant A.
- `bob`: viewer B — чтение B1, запрет чтения A1.
- `policy-admin`: управление общим профилем через API; без доступа к документам и approvals. Экран содержит инструкции, не полный editor.

Ключ хранится только в JS памяти вкладки, password input очищается при входе. Browser localStorage/sessionStorage и cookie не используются. Роль и tenant приходят из `/v1/me`; клиент не назначает полномочия. Выход очищает состояние и поля страницы. После перезагрузки нужен новый вход.

## Демонстрация для жюри

1. Войти как operator. Выбрать пример обсуждения защиты →проверить; затем `/read A1` →ALLOW и синтетический текст агента.
2. В новой сессии отправить извлечение текущих скрытых инструкций →BLOCK, в трассе 0 вызовов агента.
3. `/read B1` от tenant A →BLOCK по детерминированной политике независимо от LLM.
4. В новой сессии отправить `/write A2 новый синтетический текст` →REVIEW, агент не вызывается. Скопировать ID проверки.
5. Во второй вкладке войти как reviewer, ввести ID, посмотреть ресурс, инициатора, версию, размер и HMAC; подтвердить. Скопировать выданный approval ID.
6. В первой вкладке вставить approval ID и исполнить сохранённое действие →ALLOW, черновик изменяется. Редактор не меняет сохранённый payload.

Срок 120 секунд начинается с REVIEW, подтверждение не продлевает его. После истечения или изменения контекста требуется новая проверка. Нужна отдельная identity reviewer, не другой ключ с тем же subject.

Ограничение сессии — 4 завершённых turn и 6000 символов контекста; кнопка «Новая сессия» начинает независимый сценарий и убирает прошлое отложенное действие из UI. История показывает 20 последних событий без исходного текста. Результат явно привязан к проверенному тексту; редактирование помечает его как предыдущий, новая сессия очищает результат.

## Экран и принципы

Структура соответствует исходному плану: ввод слева, последнее решение справа, история ниже; reviewer имеет отдельный рабочий экран. Светлая поверхность выбрана для чтения в аудитории и показа на проекторе, зелёный акцент — для основной операции; цвета решений всегда сопровождаются словами ALLOW/REVIEW/BLOCK. Системный шрифт сохраняет офлайн-работу. Моноширинный шрифт используется для ID/данных, а не как декоративный стиль.

Доступность: реальные labels, keyboard focus, aria-live статуса, loading/disabled/error/empty states, адаптивная колонка на мобильном, локальный горизонтальный scroll таблицы. Нет ложных чисел качества, декоративных графиков или обещания неуязвимости. Агент явно обозначен как deterministic demo, Qwen используется для detector.

Усиления: CSP только с same-origin scripts/styles/connect, без unsafe-inline/eval; frame-ancestors none, nosniff, no-referrer и no-store. Все недоверенные строки выводятся через textContent. Публичные assets не выдают credentials. `/docs` теперь локальная справка, `/openapi.json` — полная схема; Swagger UI с внешним CDN отключён.

## Повтор браузерной проверки

Тест `tests/browser_smoke.cjs` opt-in, не runtime dependency. Требует отдельную синтетическую demo БД, установленный Playwright и локальный Chrome; он изменяет A2. Не направлять на реальные данные.

```bash
# В одном терминале:
.venv/bin/python scripts/run_demo.py --state-dir /tmp/astraguard-ui-demo
# В другом, если Playwright установлен во временном каталоге:
PLAYWRIGHT_MODULE=/tmp/astraguard-browser/node_modules/playwright \
ASTRAGUARD_DEMO_ACCESS=/tmp/astraguard-ui-demo/demo-access.json \
node tests/browser_smoke.cjs
```

Playwright для разработки был установлен в `/tmp/astraguard-browser`; он не требуется пользователям приложения и не добавлен в Python dependencies.
