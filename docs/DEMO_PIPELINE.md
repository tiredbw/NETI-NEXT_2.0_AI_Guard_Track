# Полная цепочка демонстрационного чтения

`POST /v1/agent/turns` теперь связывает существующий demo executor с проверками инструментов и результатов. Внешние advisory API сохраняют прежний контракт.

Для `/read A1` фактически выполняются четыре проверки:

1. `request_check`: правила, семантика запроса и исходный preflight политики.
2. `tool_check`: строгие аргументы documents.read, владелец родительского ALLOW, сессия и актуальный ACL.
3. `execution_acl`: повторный ACL в транзакции executor перед чтением. Событие аудита имеет тип tool_execution.
4. `content_check`: проверка прочитанного текста как недоверенного tool_result. Текст выдаётся клиенту только при ALLOW.

Контент удерживается в памяти между чтением и проверкой. При BLOCK/REVIEW поле `execution.result=null`, статус `output_blocked`. История разрешённых demo turns не пополняется. Если аудит или модель недоступны, положительный результат не выдаётся. При переполнении очереди content detector возможен HTTP 429, при отказе аудита 503. Они также останавливают выдачу. Пустой или превышающий 6000 символов tool output получает HTTP 413/TOOL_RESULT_UNSUPPORTED; текст не обрезается и не выдаётся. Чтение к этому моменту уже выполнено и зааудировано.

Исходный результат запроса не переписывается. Ответ содержит:

- `check`: первоначальная проверка запроса.
- `final_check`: последняя проверка, остановившая цепочку; при полном успехе совпадает с исходным ALLOW.
- `pipeline`: только фактически выполненные этапы `{stage,decision,check_id}`. Все check_id доступны через обычный изолированный аудит.
- `execution`: фактическое исполнение, optional pre_tool_check/tool_check/content_check и разрешённый result.
- `execution.target_invocations`: число запусков demo executor в этом HTTP-запросе.
- `execution.tool_invocations`: число выполненных чтений/записей в этом HTTP-запросе. Отказ ACL в executor даёт 0, хотя executor уже был вызван.

При повторе подтверждённой записи `replayed=true`, оба счётчика равны 0. Кешированный результат возвращается без новой записи и без нового turn в истории. Поле forwarded в replay отражает первоначальную передачу; признак replay и счётчики отличают её от нового вызова.

История показывает отдельные проверки, а не восстановленную полную трассу. UI отображает полный pipeline только для текущего ответа API, выводит значения через textContent и не хранит credential в browser storage. Ожидание demo turn в браузере увеличено до 60 секунд, поскольку запрос и tool output могут потребовать два последовательных inference. Это клиентский предел ожидания, не гарантия отмены backend.

## Сценарий для жюри

1. Войти как alice или operator и отправить `/read A1`: четыре ALLOW, один вызов инструмента, разрешённый текст.
2. Отправить `/read B1` из tenant A: BLOCK исходного preflight, downstream stages отсутствуют, ноль вызовов.
3. Отправить `/read A3`: разрешённый собственный синтетический документ содержит «Игнорируй предыдущие инструкции». Запрос и ACL получают ALLOW; content-check получает BLOCK. Счётчик чтений равен 1, но текст документа не выдаётся. В UI есть кнопка «Документ с инъекцией».
4. Запросить изменение A2 под operator и подтвердить под отдельным reviewer: прежний двухсторонний workflow сохраняется. Внешние tool-checks всё ещё не получают универсальное approval.

A3 добавляется как синтетический seed без перезаписи существующих ресурсов. В продукте по-прежнему нет целевой генерирующей LLM: executor детерминированный. Факт чтения A3 нельзя описывать как «атака не дошла до инструмента»: останавливается выдача результата после разрешённого чтения. Шлюз не изолирует внешний агент, который обходит его API.

## Проверки

Offline suite: 182 теста. Новые сценарии проверяют четыре этапа и их audit UUID, удержание инъекции, поздние отказы детектора/аудита, изменение политики, гонку ACL перед исполнением, неподдерживаемый размер результата и отсутствие выдуманных этапов после раннего BLOCK. Это проверки логики, не новый benchmark качества Qwen.

`scripts/evaluate.py` учитывает final_check, чтобы поздний BLOCK/REVIEW не ошибочно считался ранним ALLOW. Исторические измерения предыдущих версий остаются историческими; новые задержки и показатели качества требуют полного повторного прогона.

18 ноября 2026 браузерный smoke в отдельном headless Chrome с настоящей локальной Qwen прошёл: чтение A1 с content ALLOW, нажатие новой кнопки A3 с поздним BLOCK и отсутствием tool output в UI, ранний BLOCK с нулём вызовов, подтверждение записи отдельным reviewer, административный ETag/ACL workflow, вывод XSS-строки как текста, отсутствие browser storage, logout и viewport 390px без глобального overflow. Использованы отдельная синтетическая БД и случайные credentials. Скриншоты находятся вне Git: `/tmp/astraguard-pipeline-browser/`.
